## P0 · 必须修

### R1 每轮召回对早期信息基本无效（已复现）

- **位置**：`storage.py` → `SaveDB.recall_for_turn()`
- **现象**：埋针测试 **0/9 命中**。300 回合、6 个角色，在第 5、50、150 回各埋一条独特信息，第 301 回用三种问法查询，召回的 5 条全是第 286~298 回的闲聊。
- **原因**（三个叠加）：
  1. **打分让新近度压过相关度**。全文精确命中的相关度只有 0.9；而「状态里任何已知角色的最近提及」就有 0.85，再加新近度最多 0.4。第 5 回的精确命中得分约 0.96，第 294 回的无关闲聊得分约 1.36。
  2. **候选范围太窄**。每个角色只取最近 2 次提及（`LIMIT 2`）和最近 3 条事实，早期回合进不了候选。
  3. **整句输入直接当全文查询**。`MATCH` 把整句当短语，要求原文里连续出现这一整句才命中；自然问法几乎不可能命中。含引号、冒号、连字符的输入还会触发 FTS5 语法错误（现在被 `except` 吞掉）。
- **改法**：
  1. **查询词提取**（新函数 `_query_terms(player_input, known_names)`）：
     - 输入里出现的已知实体名（含别名，见 R6）；
     - 去掉常见虚词和标点后，对剩余的连续汉字片段取 2~4 字的滑动窗口作为候选词；
     - 丢弃在超过 20% 的回合里都出现的词（太常见，没有区分度），最多保留 8 个。
  2. **多词检索**：每个词单独查（≥3 字走 FTS，且**用双引号包成短语并把内部的 `"` 写成 `""`**；1~2 字走 LIKE）。一个回合命中的不同词越多，相关度越高。
  3. **重写打分**，让相关度主导：
     ```
     relevance = 2.0 × 命中的查询词数 / 查询词总数          # 全文命中
               + 1.0（输入里点名的实体在该回合被提及时）
               + 0.3（仅因为该实体在状态里、但输入没提到它）
     score = relevance + 0.5 × 重要度/10 + 0.1 × 0.98^回合差
     ```
     新近度只用来在相关度接近时排序。
  4. **实体路径的候选不再只取最近 2 次**：输入里**点名**的实体，取它**全部**提及回合参与打分；没被点名的实体最多取最近 1 次，且相关度只有 0.3。
  5. **不要召回「当前仍成立」的事实**（态度、好感度、所在等，状态摘要里已经有了）。只召回**已封口的历史事实**，并写清楚时间：`第 12~40 回：赵执事的态度是「敌视」`。
  6. 召回文本前加回合号：`[第 5 回] ……`，让模型知道这是多久以前的事（改 `prompts.build_recall_block`）。
- **验收**：把下面的埋针测试加进 `tests/test_gameplay.py`，要求 **9 条里至少命中 8 条**；并断言带引号、冒号、百分号的输入不抛异常。

```python
def test_recall_finds_early_needles(self):
    import json, os, random, tempfile, storage
    from world_state import WorldState
    random.seed(3)
    names = ["陆青鸢", "赵执事", "阿蛮", "无名老叟", "周掌柜", "林舟"]
    places = ["丹堂", "后山", "坊市", "外门执事堂", "断崖石室"]
    needles = {
        5:   ("陆青鸢", "陆青鸢压低声音：进藏经阁的暗号是青灯照壁。", "藏经阁的暗号", "青灯照壁"),
        50:  ("周掌柜", "周掌柜立下字据：欠你三百二十七块灵石，秋后归还。", "周掌柜欠我多少灵石", "三百二十七"),
        150: ("林舟", "林舟答应你：三日内替你寻回那枚碎裂的玄龟玉佩。", "林舟答应帮我找什么", "玄龟玉佩"),
    }
    db = storage.SaveDB(os.path.join(tempfile.mkdtemp(), "t.db"))
    st = WorldState()
    for n in names:
        st.data["characters"][n] = {"description": "x", "attitude_toward_player": "中立",
                                    "affinity": 40, "location": random.choice(places)}
    for t in range(1, 301):
        before = json.loads(json.dumps(st.data))
        st.data["meta"]["turn"] = t
        st.data["location"] = {"name": random.choice(places), "description": ""}
        if t in needles:
            who, nar, _, _ = needles[t]
            inp = f"和{who}说话"
        else:
            who = random.choice(names)
            act = random.choice(["闲聊了几句近况", "一起吃了顿饭", "讨论了修炼心得",
                                 "擦肩而过点头致意", "商量了坊市的行情"])
            nar, inp = f"你与{who}{act}，没有什么特别的事发生。", f"找{who}"
        db.record_turn(t, "action", nar, player_input=inp, update={}, state=st.data, state_before=before)
    hits = 0
    for t, (who, _nar, q, key) in needles.items():
        for query in (q, f"问{who}：" + q, q[-4:]):
            got = db.recall_for_turn(query, st.data, 301)
            hits += any(key in x["text"] for x in got)
    self.assertGreaterEqual(hits, 8)
    for weird in ('他说"你好"', "A-B: 测试", "100% 确定", "（）、。"):
        db.recall_for_turn(weird, st.data, 301)   # 不应抛异常
```

### R2 属性参与判定后，属性增减没有上限（已复现）

- **位置**：`world_state.py` → `apply_update()` 的 `attribute_events`；`game.py` → `_handle_judgment()` 里按属性换算因素的那段（P2-19 新增）
- **现象**：`attribute_events: [{"attribute": "魅力", "delta": 1000000}]` 原样生效。P2-19 之后属性会换算成判定因素，所以模型写一条就能让相关判定永久拿满加成。
- **改法**：
  1. 单条事件的 `delta` 钳制在 `±20`；同一属性单轮累计变化钳制在 `±20`。
  2. 参与判定的属性（换算表里列出的那些）总值钳制在 `0~200`；其他自由属性钳制在 `±10000`。
  3. 属性换算成因素时，只按**上一回合结束时**的值算（本回合刚写入的增量不参与本回合的判定）。
- **验收**：对新 `WorldState` 应用上面那条更新后，`魅力 ≤ 20`；连续 20 轮各加 20，最终 `≤ 200`。

## P1 · 应该修

### R3 消失的东西，事实不会关闭（已复现）

- **位置**：`storage.py` → `_sync_entities()` / `_apply_state_entities()` / `_set_facts()`
- **现象**：物品用完后，库里仍是 `持有 = 1，valid_to_turn = NULL`（至今有效）。角色从状态里移除、剧情标记被删、角色的某个属性被清空，同理。代码只处理了「值变了」，没处理「没了」。
- **改法**：`_sync_entities` 里对比前后状态，对「回合前有、回合后没有」的物品 / 角色属性 / 剧情标记，把对应的开放事实封口（`valid_to_turn = 本回合`）。物品额外插入一条 `持有 = 0`，方便查「什么时候用掉的」。
- **顺带修两处**：
  - 「回合前状态」里尚未入库的事实，现在会以**本回合**为起点写入、又立刻被封口到**上一回合**，出现 `valid_to < valid_from` 的区间。回合前状态的事实应以 `本回合 - 1` 为起点。
  - `entities.name` 全局唯一，同名的人物和地点会撞在一起。改成 `UNIQUE(kind, name)`，查询时带上 `kind`（需要给老库写一步迁移，`SCHEMA_VERSION` 升到 4）。
- **验收**：物品从背包移除后，`entity_profile(物品)["facts"]` 里不存在 `valid_to_turn is None` 且值大于 0 的「持有」事实；全库不存在 `valid_to_turn < valid_from_turn` 的行。

### R4 写库失败完全静默

- **位置**：`game.py` → `_record_turn()` 和 `_recalled_memories()` 的 `except Exception: pass`；`storage.py` 里多处 `except sqlite3.Error: pass`
- **现象**：写库出错直接吞掉，库里缺了回合没有任何痕迹。这和「保证不丢」的目标相反。
- **改法**：
  1. 用标准库 `logging` 记录异常（带回合号和堆栈），日志写到 `save/wanjie.log`。
  2. `Game` 上维护 `storage_errors` 计数，并把「最后成功写入的回合号」存进状态的 `meta`（或 `.db` 的 `meta` 表）。
  3. 下一回合写库前检查：库里最后的回合号是否等于当前回合 - 1。有缺口时，用当前的 JSON 状态补一条 `kind="gap"` 的记录和一份快照，保证库能继续用。
  4. `app.py` 侧栏在开启了 SQLite 且 `storage_errors > 0` 时显示一行提示：「历史库有 N 回合未写入」。
- **验收**：`patch storage.append_turn` 抛异常跑一回合 → 游戏正常继续、`storage_errors == 1`、日志里有记录；恢复后下一回合写入时库里出现 `gap` 记录。

### R5 存了两套完整状态，库会线性变大

- **位置**：`storage.py` → `record_turn()` 的 `state_after_json`、`snapshots`、`load_state()`
- **现象**：每回合都把完整状态写进 `state_after_json`，`load_state()` 也直接用它。所以「每 10 回合快照 + 增量回放」实际上从不执行；同时库大小随回合数线性增长（每回合一份完整状态）。
- **改法**（二选一，推荐 a）：
  - a. **去掉 `state_after_json`**，只保留快照 + 增量。代码侧的改动（回合号、日历、死亡、扣血等）要么并入 `update_json`，要么另存一个很小的 `system_json` 字段，回放时一并应用。加一条测试：对任意存档，`load_state()` 的结果与 JSON 主存储**完全相等**。
  - b. 保留 `state_after_json`，删掉 `snapshots` 表和回放逻辑，并在文档里写明「这是每回合全量状态日志，不是事件溯源」。
- **验收**：跑 50 回合（含战斗、判定、岁月结算）后，`load_state()` 与 `state.json` 逐字段相等；方案 a 下 `.db` 大小明显小于改动前。

### R6 别名表没有被使用

- **位置**：`storage.py`（`aliases` 表已建，但没有任何写入）
- **现象**：玩家输入「陆师姐」匹配不到实体「陆青鸢」，按名字的精确检索对称呼无效。
- **改法**：
  1. 自动别名（纯代码）：角色首次入库时，生成「姓 + 常见称谓」的候选（师姐 / 师兄 / 掌柜 / 执事 / 长老 / 前辈 / 道友…），**只在该候选不与其他实体冲突时**写入；全名去掉姓的部分（「青鸢」）也作为别名。
  2. 模型声明别名：`tools.py` 的 `characters.<名>` 增加可选字段 `aliases`（字符串数组，最多 3 个，每个 ≤ 8 字）；`world_state` 只做类型清洗后原样存进角色信息，由 `storage` 同步进 `aliases` 表。别名冲突时保留先到的。
  3. `recall_for_turn` 和 `_sync_entities` 的名字匹配都要同时匹配别名。
- **验收**：存在角色「陆青鸢」且无其他陆姓角色时，输入「问陆师姐当年的事」能召回她的历史回合；有两个陆姓角色时，「陆师姐」不被自动写成别名。

## P2 · 有空再修

### R7 地址栏 `?slot=` 能读任意命名存档
- **位置**：`app.py` → `restore_session_slot()` / `_slot_from_query()`
- **现象**：本地玩没问题。部署到公网后，任何人在地址栏写 `?slot=111` 就能读到别人起名为 111 的存档。
- **改法**：地址栏只接受以 `临时-` 开头的槽名；临时槽名从 6 位数字改成 `secrets.token_urlsafe(12)`（不可猜）。命名存档后刷新，通过「继续存档」列表读取，不走地址栏。

### R8 迁移脚本的回合号从 1 重新编
- **位置**：`storage.py` → `migrate_from_json()`
- **现象**：旧存档只剩最近 3 轮原文，迁移时编号为 1、2、3，而状态里真实回合数可能是 23。之后新写入的回合从 24 开始，事实的有效期和召回的回合差都会错位。
- **改法**：以 `state["meta"]["turn"]` 为最后一回合的编号，往前倒推。
